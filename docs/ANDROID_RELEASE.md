# A3LAM — Android Release Handoff

## Application identity

| Field | Value |
|---|---|
| App name | `A3LAM | أعلام` |
| Application ID | `org.a3lam.app` |
| Production origin | `https://a3-lam.vercel.app` until an approved custom domain is configured |
| Wrapper direction | HTTPS web wrapper / Capacitor-compatible foundation |
| Cleartext traffic | Disabled |

The wrapper must use the existing web application rather than reimplementing A3LAM natively. Keep RTL, deep links, back navigation, external-link policy, offline/error states, and accessible focus behavior aligned with the web release. Never embed database URLs, Admin tokens, provider secrets, private keys, or manually managed session secrets.

## Debug and release separation

Use a debug application or internal track for testing. Keep production origin and release configuration separate from debug logging and test endpoints. Do not add HTTP cleartext exceptions. Validate deep links, back handling, external URLs, orientation, keyboard/focus, RTL, network failure, and session behavior on a real device before release.

## Signing requirements

1. Create or import a release keystore on a controlled operator machine.
2. Store keystore bytes and passwords in a secret manager or CI secret store, never in Git or the APK source tree.
3. Record the application ID and signing certificate fingerprints in the release inventory.
4. Build a signed AAB/APK in the approved external environment and verify its checksum.
5. Keep upload-key rotation and recovery contacts documented separately.

No keystore is generated by this repository or by Phase 17.8.

## Play Store checklist

Complete identity, privacy policy URL, data-safety declaration, content rating, screenshots, icon/splash assets, target SDK review, signing enrollment, internal testing, crash monitoring, and staged rollout. Verify that the published app points only to the approved HTTPS origin and that no admin-only route is embedded as a default entry point.

## Versioning

Use a monotonic Android `versionCode` and a human-readable `versionName` tied to the web release commit. Record the web commit, wrapper commit, build environment, signing identity, and artifact checksum for every release.
